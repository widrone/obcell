## Goal

`tests/lxd/radio-smoke.sh` proves the whole data path with no RF: the ZeroMQ gNB plus
srsUE attach, get a PDU session, and ping the core.

## Context

- The e2e part of `radio-smoke.sh` was written on 2026-11-21 and **has never run**.
- The srsue role builds srsRAN_4G and writes `~/gnb_zmq.yml` (band 3 FDD, 20 MHz, SCS 15,
  23.04 Msps) and `~/ue_zmq.conf` (netns `ue1`, the test SIM). These follow the srsRAN
  Project ZMQ tutorial.
- The script starts the gNB with `gnb_zmq.yml`, then srsUE. It waits up to 120 s for
  `PDU Session Establishment successful` in `/tmp/e2e-ue.log`, then runs
  `ip netns exec ue1 ping 10.45.0.1`.
- `gnb-n40` (the unit) and the e2e gNB use the same ZMQ ports, so the unit is stopped first.

## Steps

1. On a built container (task 002): `tests/lxd/radio-smoke.sh 22.04`.
2. If e2e fails, read the gNB and UE logs it prints. Usual suspects:
   - timing (the UE started too early or late);
   - the `ue1` namespace or the TUN device;
   - the test SIM not provisioned (check the WebUI or with mongosh);
   - the Open5GS SMF/UPF not giving a session;
   - the UPF NAT/route for 10.45.0.0/16.
3. Fix the script or the srsue templates. Keep the safety guards: ZeroMQ only, container only.
4. Run it 3 times in a row to check it isn't flaky.

- [x] Passes on 24.04 and 26.04 too, once those tasks get there (or the reason it can't is noted).
