## Goal

`secrets/<host>/` can be stored encrypted (so it could be backed up, or even committed to
a private repo), and the playbook still runs.

## Context

- Today the secrets are plain files, mode 600, git-ignored. They are generated by
  `tasks/secrets.yml`, read by the lookups in `group_vars/all/secrets.yml`
  (`password` and `file` lookups), and copied between machines by hand.
- `ansible-vault encrypt` on those files works with the `file` lookup. The `password`
  lookup writes new plain files, so generation and encryption need to cooperate.

## Steps

1. Human: decide whether this is wanted, and where the vault password lives (a password
   manager, `--ask-vault-pass`, or a vault-id script).
2. Prototype on a test host's secrets (`secrets/obcell-*`), never on a real Obcell's.
3. Make generation encrypt new files, or document the encrypt step. Make sure that
   `no_log`/`diff: false` still hide every value.

## Done when

- [ ] A decision is recorded; if yes, a test Obcell builds with encrypted secrets and the
      README explains the workflow.
