## Goal

A fresh 26.04 (resolute) box installs the whole Obcell, **installing itself** (bootstrap.sh +
ansible-core 2.20 on Python 3.14), with the same results as 22.04.

## Context

- See [docs/ubuntu-releases.md](../ubuntu-releases.md) for the 2026-11-21 checks.
- **MongoDB** doesn't publish a server for resolute yet (only the client tools).
  `mongodb_repo_release` falls back to the noble 8.0 repo; a dry-run install there resolved
  every dependency. It has not been started yet. MongoDB needs AVX on x86, which the test
  machine's CPU must have.
- **Toolchain jumps from 22.04:** gcc 11→15, cmake 3.22→**4.2**, mbedTLS 2.28→**3.6**,
  Boost 1.74→1.90, Python 3.10→3.14. Likely failures:
  - CMake 4 refuses `cmake_minimum_required(VERSION <3.5)` in srsRAN_4G or bundled
    sub-projects. Fix: add `-DCMAKE_POLICY_VERSION_MINIMUM=3.5` to the cmake args
    (`ocudu_cmake_args`, and the srsUE build).
  - srsRAN_4G 23.11 against mbedTLS 3: may need a patch, or building srsUE may need to
    become optional on 26.04 (it is only the virtual test phone).
  - gcc 15 errors (missing `<cstdint>` and similar) in the pinned sources: small patches.
- **Controller:** `passlib` is unmaintained. Check that the Authelia argon2id and Strom
  bcrypt hashing in `tasks/secrets.yml` still works on Python 3.14. If it doesn't, call
  `argon2-cffi` and `bcrypt` directly.
- A 26.04 container may already exist from an aborted attempt (`obcell-resolute`, which
  also has a hand-added MongoDB list file); use `--fresh`.

## Steps

1. `tests/matrix.sh --fresh 26.04` (inside controller is the default, which is the point
   here).
2. Fix failures as in task 003: release-neutral fixes first, per-release variables where
   needed, patches in `files/patches/`.
3. Also run `--controller outside` once, to see whether ansible-core 2.17 (Python 3.10
   controller) can drive a Python 3.14 target. If it can't, document that 26.04 Obcells need a
   newer controller.
4. Re-check 22.04 and 24.04 for regressions.
5. Update the docs.

- [x] MongoDB from the noble repo runs and verify sees the subscriber.
- [ ] 22.04 and 24.04 still pass.

## Findings

### 2026-11-22

Runs on the test machine (task 001), `OBCELL_TEST_CPUS=8 OBCELL_TEST_MEM=16GiB`, controller
inside (ansible-core 2.20.11 on Python 3.14).

| Run | Commit | Install | Health | Idempotent | NG Setup | UE e2e | Min | What failed |
|---|---|---|---|---|---|---|---|---|
| 1 | 5eaeb33 | FAIL | – | – | – | – | 5 | `PPA open5gs/latest`: "Unable to get required signing key" |
| 2 | 5e2ef1d | FAIL | – | – | – | – | 4 | WebUI build: `npm: not found` |
| 3 | 2a367ab | FAIL | – | – | – | – | 24 | srsUE build: GCC 15 `-Werror=template-id-cdtor` in `block_queue.h` |
| 4 | bd3c1f5 | PASS | PASS | PASS | PASS | PASS | 17 | (re-used container) |
| **5** | **bd3c1f5** | **PASS** | **PASS** | **PASS** | **PASS** | **PASS** | **38** | `--fresh`: from scratch |

What changed:

- **5e2ef1d:** apt 3 has no `apt-key`, and without it `ansible.builtin.apt_repository`'s PPA
  code runs `gpg --keyserver … --export <fingerprint>` without ever receiving the key, so
  it exports nothing. `roles/common/tasks/ppa.yml` now uses Ubuntu's `add-apt-repository`
  where `/usr/bin/apt-key` is missing (deb822 `.sources` with the key in `Signed-By`).
  22.04 and 24.04 keep `apt_repository`.
- **2a367ab:** resolute's own `nodejs` 22.22.1 outranks NodeSource's 20.20.2 by version,
  and has no npm. `/etc/apt/preferences.d/nodesource` pins NodeSource's nodejs at 600
  (what NodeSource's setup does); a fresh resolute box then picks `20.20.2-1nodesource1`.
- **bd3c1f5:** `roles/srsue/files/srsran4g-gcc15-block-queue-ctor.patch`, a backport of
  upstream srsRAN_4G 95aebad31cdc: `explicit block_queue<myobj>(…)` names the constructor
  with a template-id, which GCC 15 rejects. Together with task 003's two srsUE fixes, a
  `-k` build of srsUE then had no other errors.

What the Context expected but didn't happen: cmake 4.2.3 configured srsRAN_4G and OCUDU
(deprecation warnings only, no `CMAKE_POLICY_VERSION_MINIMUM` needed), mbedTLS 3.6 needed
no patch, the OCUDU gNB built with GCC 15 unchanged, and passlib's argon2id/bcrypt hashing
works on Python 3.14. MongoDB 8.0.38 from the noble repo runs (the CPU has AVX2) and
`verify.yml` sees the one test subscriber.

Not done yet: step 3 (`--controller outside` with ansible-core 2.17 driving a Python 3.14
target), the 22.04 and 24.04 regression runs, and the docs.
